# 模型调研与升级路线：YOLO、TrackNet 与当前前沿

日期：2026-11-10。用途：为“先用公开模型加微调，基础做好之后再升级模型”这个长期目标
提供依据。本文是文献和代码调研，**不包含本项目的任何新测量结果**；文中引用的精度数字
都来自各论文或发布方自己的数据集，不能直接当作本项目在转播视频上的表现。

## 1. 结论先行

| 环节 | 现在用的 | 成熟度 | 判断 |
|---|---|---|---|
| 球员检测与姿态 | YOLO26s 检测 + 姿态 | 成熟 | 不需要自研，够用 |
| 球员跟踪 | ByteTrack + 近/远端角色约束 | 成熟 | 网球只有两名球员，“每个半场一个人”的约束比换跟踪器更有效 |
| 球场标定 | 14 关键点热图 + 单应矩阵 | 数学成熟 | 转播镜头会摇移，需要逐帧更新和平滑；属于工程问题 |
| 球检测 | YOLO（COCO sports ball）默认；TrackNet 可选 | **最弱环节** | 单帧检测框不适合几个像素大的球；应转向多帧热图模型并微调 |
| 击球/弹跳时刻 | 启发式规则 | **缺口** | 应换成时序事件定位模型 |
| 拍型分类 | 无 | **缺口** | 基于姿态序列的小模型即可 |
| 三维轨迹 | 无 | 研究阶段 | 用物理仿真生成训练数据，放到最后 |

值得投入训练的是三处：**球、事件、拍型**。其余环节直接用公开模型。

## 2. YOLO 的数学基础

### 2.1 结构

YOLO 是单阶段的密集预测检测器。一张图过一次网络，同时输出所有位置上的类别和框：

1. **主干网络（backbone）**：卷积堆叠，逐级下采样，得到步长（stride）为 8、16、32 的特征图。
2. **颈部（neck）**：FPN/PAN 结构，把深层语义和浅层细节上下融合。
3. **检测头（head）**：在每个尺度的每个网格点上预测类别分数和边界框。

从 YOLOv8 起是**无锚框（anchor-free）**设计：网格点直接回归它到目标框四条边的距离
$(l, t, r, b)$，不再依赖预设的锚框尺寸。

### 2.2 损失函数

总损失是分类项和定位项的加权和。

- **分类**：逐类别的二元交叉熵（BCE）。
- **定位**：CIoU 损失，同时惩罚重叠不足、中心偏移和长宽比不一致：

  $$L_{CIoU} = 1 - IoU + \frac{\rho^2(b, b^{gt})}{c^2} + \alpha v$$

  其中 $\rho$ 是预测框和真值框中心的距离，$c$ 是两者最小外接框的对角线长度，
  $v$ 衡量长宽比差异。
- **分布焦点损失（DFL，v8–v11）**：把每条边的距离表示成若干离散区间上的概率分布，
  取期望作为预测值。YOLO26 去掉了 DFL，改回直接回归，导出和边缘设备部署更简单。

### 2.3 标签分配

训练时要决定“哪些网格点负责哪个真值框”。YOLOv8 之后用任务对齐分配
（Task-Aligned Assigner），按对齐度选前 k 个点作为正样本：

$$t = s^{\alpha} \cdot u^{\beta}$$

$s$ 是该点对真值类别的预测分数，$u$ 是预测框与真值框的 IoU。

### 2.4 去掉 NMS

传统 YOLO 一个目标会产生多个重叠的框，推理后要用非极大值抑制（NMS）去重。YOLOv10 和
YOLO26 训练时同时用“一对多”和“一对一”两个分配分支，推理只用一对一分支，每个目标只出
一个框，不再需要 NMS。按发布方的说法，YOLO26 还加入了针对小目标的标签分配（STAL）和
渐进式损失平衡（ProgLoss），CPU 推理比 YOLO11 快最多约 43%。

### 2.5 为什么 YOLO 检测网球效果有限

- **目标太小**：转播画面里球只有几个像素。在步长 8 的特征图上不足一个网格，远端更小。
- **IoU 对小目标极敏感**：5 像素的框偏移 2 像素，IoU 就掉一大半，损失和标签分配都不稳定。
- **只看单帧**：高速球是一条模糊的拖影，单帧里和线、鞋、观众席的白点很难区分。
  区分它们靠的是运动，而单帧检测器看不到运动。
- **训练数据**：COCO 的 sports ball 是各种球的混合类别，网球样本少。

本项目的实测与此一致：微调的单类 YOLO26s 在留出测试集上 0 个正确检测，未通过门槛
（见 [VALIDATION.md](../../VALIDATION.md)）。

### 2.6 YOLO 可以改进的方向

| 方向 | 做法 | 评价 |
|---|---|---|
| 提高有效分辨率 | 更大输入尺寸；切片推理（SAHI）；只在球场区域裁剪 | 简单有效，但更慢 |
| 增加浅层检测头 | 加步长 4 的 P2 头 | 对小目标有帮助，是常规做法 |
| 换小目标损失 | 用归一化 Wasserstein 距离（NWD）代替或补充 IoU | 缓解 IoU 敏感问题 |
| 多帧输入 | 把相邻帧叠在通道维 | 这其实已经在往 TrackNet 的思路靠 |

判断：继续把 YOLO 用在**球员、球拍、姿态**上；球的检测不值得在 YOLO 框架里深挖。

## 3. TrackNet 的数学基础

### 3.1 核心思路

TrackNet 不预测框，而是**预测一张热图**：每个像素是球心的可能性有多大。它输入连续多帧，
让网络自己学到“会动的小亮点才是球”。

- **输入**：连续 3 帧在通道维拼接（9 个通道），缩放到 640×360。
- **网络**：编码器—解码器。V1 是 VGG-16 风格的编码器加反卷积解码器；V2 起改成带跳跃
  连接的 U-Net，并一次输出多帧的热图（多进多出）。
- **真值**：以球心 $(x_0, y_0)$ 为中心的二维高斯：

  $$G(x, y) = \exp\left(-\frac{(x - x_0)^2 + (y - y_0)^2}{2\sigma^2}\right)$$

- **损失**：V1 把热图量化成 256 级，对每个像素做 256 类的交叉熵分类。V2 改成 sigmoid
  输出加带权二元交叉熵，让极少数的“球”像素不被海量背景像素淹没：

  $$L = -\sum \left[(1 - y)^2\, \hat{y} \log y + y^2 (1 - \hat{y}) \log(1 - y)\right]$$

  其中 $y$ 是预测值，$\hat{y}$ 是真值。
- **后处理**：对热图取阈值，再找圆或连通域的中心作为球的位置。

本项目接入的是 [yastrebksv/TrackNet](https://github.com/yastrebksv/TrackNet) 的权重，
属于 V1 风格（256 类输出加霍夫圆检测），命令行选项名是 `tracknet-v2`。

### 3.2 各版本的演进

| 版本 | 主要改动 | 备注 |
|---|---|---|
| V1（2019） | 多帧输入、热图回归 | 网球数据集；召回偏低 |
| V2（2020） | U-Net、多进多出、带权损失 | 速度和精度都明显提升；羽毛球 |
| V3（2023） | 背景估计、mixup 增强、轨迹修补模块 | 更准但更慢 |
| V4（2024） | 用帧间差分生成“运动注意力图”，作为可插拔模块 | 几乎不增加计算量 |
| V5（2025–2026） | 两篇同名工作：一篇用带符号的运动极性加 Transformer 残差修正；另一篇用 R(2+1)D 时空卷积加门控运动提示，并给出 258 万参数的轻量版 | 均为预印本或新近发表，尚无本项目的验证 |
| WASB（2023） | 高分辨率主干、位置感知训练、在线跟踪 | 多种球类的强基线，含网球权重 |

V5 两篇论文各自报告 F1 约 0.985，但测试集分别是 TrackNetV2 数据集和羽毛球数据集，
评判标准是 4 像素内算命中。这些数字不能直接类比到转播网球。

### 3.3 TrackNet 的已知弱点和可改进之处

| 弱点 | 表现 | 改进方向 |
|---|---|---|
| 输入分辨率低 | 640×360 下远端球不到 2 像素 | 提高分辨率，或先裁出球场区域再推理 |
| 没有置信度 | 当前接入的版本只给位置，本项目用常数 0.5 代替 | 用 sigmoid 热图峰值作为置信度，才能做阈值和校准 |
| 每帧只出一个球 | 场上有备用球、球童手里的球时会选错 | 输出多个候选，交给时序门控选择 |
| 时序信息利用浅 | 只是把帧叠在通道上 | 运动注意力（V4）、带符号运动（V5）、时空卷积 |
| 遮挡和出画 | 球被球员挡住或飞出画面时乱跳 | 轨迹修补；对抛物线做物理约束的后处理 |
| 域外泛化 | 换球场颜色、机位、压缩质量就掉点 | 用转播数据微调，加入难负样本（记分牌图标、白鞋、观众席） |

本项目 11 月的转播测试里，这些问题大多出现过：TrackNet 额外找到的球里有白鞋和场外的球，
YOLO 误检过记分牌上的发球图标。

## 4. 其他环节的前沿做法

### 4.1 目标检测：Transformer 检测器

2025–2026 年实时检测的主要变化是 DETR 系列追上并在精度上超过了 YOLO：

- **RT-DETR**（2023）：第一个在速度上追平 YOLO 的 DETR，用混合编码器，无需 NMS。
- **D-FINE**（2024）：把框回归改成对概率分布的逐层细化。Apache 2.0。
- **RF-DETR**（2025）：DINOv2 预训练主干加可变形注意力，发布方称其为首个在 COCO 上
  超过 60 AP 的实时检测器，小数据集上迁移效果好。Apache 2.0。

对本项目的意义：球员检测已经够用，换它们收益不大。它们的价值在两点，一是许可更宽松
（Ultralytics 是 AGPL-3.0），二是预训练主干在少量标注下微调效果好。

### 4.2 多目标跟踪

- **ByteTrack**：卡尔曼滤波预测每条轨迹的位置，用 IoU 做代价矩阵，匈牙利算法求最优匹配；
  特点是把低分检测也拿来做第二轮匹配，减少遮挡时的丢失。
- **OC-SORT**：用观测而不是预测来修正轨迹，对非线性运动更稳。
- **BoT-SORT**：加入相机运动补偿和外观特征。
- **Deep-EIoU**：把框放大后再算 IoU，针对运动员快速移动。

网球转播只有两名主要球员，隔网站位，跟踪本身很简单。难点是球童、线审、裁判被当成球员，
以及镜头切换后的身份延续。这些靠球场坐标约束和人工确认的身份映射解决，项目里已有。

### 4.3 姿态估计

YOLO 姿态、RTMPose/RTMO、ViTPose、Sapiens 都能给出 17 个关键点。精度上后几者更高，
但本项目对姿态的用途（脚点、手腕、判断正反手）不需要顶级精度。保持现状。

### 4.4 事件定位（击球、弹跳）

这是和本项目目标最相关的前沿方向，叫做精确事件定位（precise event spotting）：

- **E2E-Spot**（2022）：逐帧的轻量图像特征加双向 GRU，直接输出每一帧是不是事件。
  配套的网球数据集标了近/远端的触球和弹跳。
- **T-DEED**（2024）：在时序上做编码—解码，提高相邻帧的可区分度。
- **F3ED**（2025，F3Set 配套）：针对“快、密、细粒度”的事件，同时输出拍型、方向等多个属性。

本项目可以走更轻的路线：不直接吃图像，而是用已有的球轨迹、球员姿态和球场坐标作为特征，
训练一个小的时序模型（GRU 或一维卷积）。数据需求和算力都小得多。

### 4.5 单目三维球轨迹

思路是物理约束而不是直接回归：一拍从击球到落地近似服从重力加空气阻力的运动方程，
两端点（击球、落地）已知时，用重投影误差拟合初速度。近期工作都用物理仿真生成训练数据。
已知困难是远端球员的起点和高球的高度估计误差大。

### 4.6 视觉基础模型

SAM 2 这类视频分割模型和 DINOv2/v3 这类自监督主干在通用跟踪上很强。对球员分割、
主机位镜头识别有潜力；对几个像素大的球帮助有限，而且计算量大，不适合逐帧跑整场比赛。

## 5. 升级路线

每一步都在同一个冻结的基准集上和上一步比较，过了门槛才替换默认模型。

| 阶段 | 内容 | 前提 |
|---|---|---|
| M0 基准集 | 用公开转播标注（TrackNet、Spot、F3Set）加自己复核的比赛，按比赛分组建立训练/验证/测试集 | 球路复核流程可用 |
| M1 微调现有模型 | 用网球转播数据微调现有 TrackNet 权重；加入难负样本；补上置信度输出 | M0 |
| M2 换更强的公开结构 | 在同一基准上比较 WASB、TrackNetV4/V5 风格的运动输入；选通过门槛的那个 | M0、M1 |
| M3 事件与拍型模型 | 基于轨迹加姿态特征的时序模型，替换启发式击球/弹跳检测；正反手分类 | M0；球追踪达到可用水平 |
| M4 自研模型 | 见下 | M1–M3 都有明确的剩余误差分析 |

### M4：如果要训练自己的模型，值得尝试的设计

这些是基于第 3 节弱点提出的设计方向，都还没有验证：

1. **球场感知的输入**：先用单应矩阵把画面裁剪或校正到球场区域，再送进热图网络。
   远端球的像素数增加，观众席和记分牌直接被排除在外。
2. **带符号的运动通道**：除了 RGB，额外输入相邻帧的正、负差分，让网络直接看到运动方向。
3. **球和事件联合输出**：同一个网络同时输出球的热图和“这一帧是否击球/弹跳”。
   两个任务共享时序特征，弹跳本来就是轨迹上的拐点。
4. **多候选加物理一致性**：网络给出每帧的多个候选，再用抛物线段拟合选出整条轨迹，
   而不是逐帧取最大值。
5. **蒸馏到小模型**：先训练一个精度优先的大模型做标注和教师，再蒸馏成能逐帧跑完整场的小模型。
